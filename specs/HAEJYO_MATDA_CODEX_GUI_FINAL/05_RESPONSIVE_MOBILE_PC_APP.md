# 모바일 / PC / 향후 앱 설계

## 1. 우선순위
개인 서비스는 모바일 70~80% 우선의 사고방식으로 설계한다.
B2B 계약관리·입찰은 PC 중요도가 더 커질 수 있다.

## 2. 모바일
### 고정 골격
상단:
- 로고/브랜드
- 지역
- 검색
- 알림(필요 단계부터)

하단:
- 홈
- 글쓰기/요청 `+`
- 채팅
- MY

터치타깃 최소 44px 수준을 목표.
Safe area 고려.

### 홈 Phase별
#### Community
검색 + 필터 + 바로 피드.

#### Quotes
검색 + 6개 카테고리 + 최근 요청 + 커뮤니티.

#### Provider
검색 + 카테고리 + 추천업체(가로스크롤) + 요청 피드.

#### BIZ
브랜드/색 언어는 유지하되 업무용으로 조금 더 정돈.

## 3. PC
PC를 모바일 카드 하나를 가운데 크게 두는 방식으로 끝내지 않는다.

### 초기 커뮤니티
- 좌측 180~220: 카테고리/필터
- 중앙 620~760: 피드
- 우측 240~300: 글쓰기/내활동/인기글

### 견적/업체 단계
- 헤더 검색 강화
- 중앙 요청/견적
- 우측 추천업체/내활동
- 필요 시 히어로 1개

### BIZ
- 검색/카테고리
- 기업 요청/RFQ
- 우측 내 사업장/마감 예정

## 4. 반응형 breakpoint
정확한 px은 프로젝트 디자인시스템에서 결정하되:
- mobile: 1열
- tablet: 1~2열
- desktop: 2~3열

컴포넌트와 데이터는 동일하고 배치만 변화한다.

## 5. 앱 준비
초기에는 웹을 먼저 완성한다.
나중에 네이티브 앱을 만들더라도:
- Supabase/backend contracts 공유
- API 타입 공유
- 디자인토큰 공유
- 비즈니스 로직 공유 가능한 부분 분리

모바일 웹 UI를 앱 디자인 기준으로 삼는다.
