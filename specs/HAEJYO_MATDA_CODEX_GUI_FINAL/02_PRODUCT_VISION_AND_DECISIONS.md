# 제품 비전과 확정 결정사항

## 1. 서비스는 ‘더블 플랫폼’처럼 보이면 안 된다
소비자 커뮤니티/견적과 B2B가 기술적으로 다른 기능을 갖더라도, 사용자에게는 **같은 플랫폼이 점진적으로 깊어지는 느낌**이어야 한다.

- 초기: 커뮤니티가 중심
- 민간견적: 구해요가 구조화된 견적으로 진화
- 업체마켓: 사용자가 직접 업체 탐색 가능
- BIZ: 동일한 요청/견적 엔진을 기업 업무에 확장
- 계약관리: MY 안에서 깊어짐
- 입찰: BIZ의 별도 조달 기능

## 2. 홈의 변화
### Phase 1
커뮤니티 피드가 첫 화면.

### Phase 2
검색/6개 카테고리/견적 CTA가 상단으로 승격.
구해요 카드에 `견적 3/5` 같은 상태 추가.

### Phase 3
업체찾기/추천업체가 추가되지만 커뮤니티는 유지.

### Phase 4
헤더에 `기업서비스` 진입점 추가.
소비자 홈은 유지하고 `/biz`에서 기업용 메인 제공.

즉, 기능이 추가될수록 `삭제`가 아니라 `승격/강등`한다.

## 3. 브랜드
작업명:
- Consumer: 해죠
- Business: MATDA BIZ
- Parent: MATDA

가능한 표현 예:
- 소비자: `해죠` 또는 `해죠 by MATDA`
- 기업: `MATDA BIZ`

한 사업자가 두 서비스브랜드를 운영할 수 있는 구조를 전제로 하되 법인/사업자 확정은 별도 의사결정이다.

## 4. 계정
소비자와 B2B는 하나의 계정 인프라를 재사용할 수 있다.
한 사용자가 다음 역할을 동시에 가질 수 있다.
- 일반 사용자
- 서비스 제공자/업체
- 기업 담당자

단, 별도 심리/상담 전문플랫폼은 브랜드/회원경험을 분리하는 전략을 유지한다.

## 5. 초기 무료
활성화 우선:
- 회원가입 무료
- 글 무료
- 업체 등록 무료
- 견적 무료
- 채팅 무료
- 중개수수료 0
- 결제 기능 필수 아님

유료화는 거래가 생긴 뒤:
- 업체 노출
- CRM
- 고급 통계
- 자동 알림
- 견적 템플릿 고급기능
- 결제/안전결제
등으로 확장 가능.

## 6. ‘활성화’의 정의
단순 DAU보다 다음 퍼널을 본다.

`구해요 글 수 → 견적 도착률 → 채팅률 → 업체 선택률 → 실제거래 확인률 → 후기율 → 재사용률`

커뮤니티 게시글이 적다고 다음 개발을 멈추지 않는다.

## 7. 장기 사업 연결
소프트웨어 이후의 장기 비전은 별도다.
- 안전/전기/시설 대행업체 매칭
- 수요가 검증되면 직접 대행업 진입 검토
- EV/Fleet 유지관리·충전·주차·세차
- 장기적으로 모빌리티 인프라

이 비전은 코드 MVP에 직접 넣지 않는다.
