# 제안 중심 견적 흐름 — 2026-09-20

이 문서는 Phase 2의 기존 ‘가격 + 설명 필수’ 규칙을 대체한다. 커뮤니티 요청 링크와 기존 견적은 유지한다. 운영 공개 승인은 별도다.

## 고객과 업체의 흐름

요청 한 번 작성 → 업체가 제안 → 공통 추가정보 한 번 답변 → 관심 업체와 상담 → 최종 확정 견적 → 업체 선택.

- 확정 견적: 금액과 한줄 설명 필수. 포함 범위·작업시간·일정·추가비용은 선택.
- 예상 견적: 최소/최대 금액·가격 변동 조건·한줄 설명 필수.
- 확인 후 견적: 확인할 사항·상담/방문 가능 일정·상담/방문비·한줄 설명 필수. 작업 금액은 null이며 0원으로 표시하지 않는다. 비대면 사진 확인도 이 유형을 쓴다.
- 제안은 기존 5개/추가 5개 슬롯을 사용한다. 유형 변경·최종 견적은 같은 제안을 수정하므로 슬롯을 추가로 쓰지 않는다.
- 예상/확인 후 제안은 상담 가능하나 업체 선택 불가. 확정 견적으로 수정한 뒤 선택한다.
- 모집기간 종료는 신규 업체 참여를 막는다. 기존 업체는 업체 선택 전까지 제안을 수정하고 공통 질문에 참여할 수 있다. 선택 후 제안 수정은 불가.
- 고객에게 도착한 제안 전체, 업체에게 본인이 보낸 제안만 보인다. 제안 유형·금액·상담 내용은 제3자에게 비공개. 공개 요청과 총 모집 현황은 유지한다.

## 반복 질문 줄이기

제안을 보낸 업체가 ‘추가정보 요청’으로 공통 질문을 남긴다. 고객의 공유 동의를 받은 답변은 요청 상세의 ‘요청 공통 추가정보’에 반영되어 모든 제안 참여 업체에게 보인다. 공개 요청 본문에 답변을 노출하지 않는다.

- 기존 질문/답변을 먼저 확인하도록 안내한다. 공백·대소문자를 정규화한 동일 질문은 같은 항목을 반환한다. 의미가 같은 다른 문장을 자동 판별하는 기능은 아니다.
- 요청당 질문 20개, 질문 200자·답변 2000자 제한. 답변 수정 가능.
- 요청자만 답변하며, 비로그인·다른 고객·미참여 업체는 조회 불가. 차단·정지 권한을 적용한다.
- 연락처·상세 주소·개별 협상은 1:1 채팅으로 안내한다. 자유 입력 민감정보 자동 탐지/삭제 기능은 포함하지 않는다.
- 개별 채팅에서 합의한 최종 금액과 범위는 업체가 제안에 반영한다. 채팅 내용 자동 전사는 하지 않는다.

## 구현과 적용

공통 최소 폼으로 시작하고 업종별 복잡한 필수 견적서는 만들지 않는다. 업체 역할 전환은 같은 계정의 MY 또는 타인 요청의 ‘업체로 참여하기’에서 가능하다. 관리자 역할은 자동으로 업체로 강등하지 않는다.

SQL `0018_proposals_and_shared_questions.sql`을 0017 다음에 별도 staging에 적용한다. 구 견적은 fixed로 호환한다. RPC·RLS를 포함하며 공개 플래그를 켜지 않는다. 실제 원격 적용은 하지 않았다.

되돌릴 때는 Phase 1/DB 공개 플래그 false로 닫는다. inspection의 null 금액 때문에 구 Phase 2 코드로 그대로 되돌리는 것은 지원하지 않는다. 데이터 삭제나 금액을 0으로 치환하지 않는다.

검증: 로컬 도메인 및 실제 SQL/PGlite의 유형 검증·선택 차단·동일 질문·답변 동의/권한·만료 후 최종 견적, PC/모바일 브라우저의 유형별 입력·공유·최종 전환·비교.

검증 결과: 단위/DB 46개, Phase 2 PC/모바일 E2E 6개, 타입·lint·Next 프로덕션 빌드 통과. 실제 원격 환경 검증은 별도다.
